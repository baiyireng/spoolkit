# 设计取舍与踩过的坑

对外文档只讲"怎么用"。这一页收那些**长段理由**：为什么这么定、不这么定会怎样。每条只给结论与
指针，详细推演与实测账在 [`dogfooding.md`](dogfooding.md) 与 [`superpowers/specs/`](superpowers/specs/)。

## 配置三层

命令行 > 环境变量 > 用户配置 > 内置默认，因为它们是三种不同寿命的意图：命令行是"这一次"、环境
变量是"这个 shell"、配置文件是"长期"。少了用户级那层，同一件事每天要重打一遍
`--provider llamacpp --base-url …`，而重复输入的下场是有人做个 `.bat`，然后没人知道真正的配置在哪。

密钥只放 `.env`、非密钥默认值只放 `config.toml`：`config.toml` 的键是白名单（写错一个字母的症状
是"设置了却没生效"，最难查），而密钥得能随手加一行、能被 `.gitignore` 一句话排除。

## cwd 契约

CLI 认当前目录（往上找 `.agent/`），机器级入口不认。说不清就让主人点名，不拿"你站在哪"顶数——
猜错的症状是"这个命令的记忆跟别的命令不是同一份"。

2026-09-27 的事故：在 `C:\Users\32615` 起桥，它去找 `C:\Users\32615\.env`，而凭据在
`D:\workSpace\agentWorkSpace\.env` 里；更坏的是 `cwd/.env` 在解析顺序里**排在用户级前面**，于是
"照着提示在脚下建一个 .env"反而静默压掉了正确配置。现在的规矩是没给 `--root` 就是 `None`，凭据只
从用户级那层来。

迁移口径：`serve` / `hub` 不给 `--root` 时不再认 cwd，是本批唯一一处默默改掉的老行为。唯一例外是
机器级桥在登记表为空时退回启动目录——否则装机第一天没人能完成第一次配对；这条兜底刻意限死在
"一个工作区都没登记过"。

## 机器级入口与短命令

网页壳本来就是机器级的（不认 cwd），但它的名字叫 `hub`；而"在任意目录敲一下就能起手"这件事，
**名字短本身就有一半功劳**。所以有了 `spool web` / `spool qq` 两条短写；`serve` / `hub` / `bridge`
原样保留、语义不变——改长命令等于改既有行为。

`[channel.<名字>]` 只给短命令当默认值，`bridge` 的参数默认值一个字没动。那节里的 `root` 认但不读：
工作区在早得多的一步就解析完了，回头拿配置去补等于把"服务整台机器"这条契约改掉。

## 通道与凭据

默认**配对**而不是默认放行：公网通道 + 一个能驱动工作区的 agent，默认放行是致命的（第三方 hook 的
访问控制在名单为空时会放行任何发送者，那正是这里要避免的）。

放行做成**身份级**（哪条通道 + 哪个用户 → 能碰哪几个工作区），与工作区解耦，所以换工作区不用重新
配对。凭据链只有一处实现，因为三处各写一套的下场是"这条命令能读到、那条读不到"，而报错还都写着
"没配"。

通道本身是**可装载**的（entry point 组 `spoolkit.channels`，或环境变量
`SPOOLKIT_CHANNEL_PLUGINS`）：核心不认识任何一家通道，接一家新的不必改核心。**个人微信与个人 QQ
没有公开的官方接口**——第三方 hook（itchat / wechaty / NapCat 之类）违反服务条款、有封号风险，而且
等于把配对、长度上限、授权这三件事全绕过去了，所以这个包只做官方通道。

## 长连接与渲染

QQ 网关的心跳与握手字节流各有一次真机才露出来的时序错（心跳迟发被判掉线；握手时多读到的数据帧被
丢掉，症状是"偶发连不上"，单跑必过、全量才炸）。两条都已修，其中丢帧那条被固定成确定性用例——
偶发问题不固定成用例就修不住。

手机上看到的文字按各通道渲染能力处理（只动标记、不改内容），因为让模型"别写 Markdown"既不可靠、
又白占这个项目的命根子（上下文预算）。

## 异步与协议

MCP 的一次 `tools/call` 是请求/响应，而这里的任务可以跑几十分钟；做成同步，调用方不是干等就是超时
——两样都不对。所以 `delegate_task` 立刻返回 task_id，进度靠 `task_status` / `task_events` 轮询，审批
靠 `confirm_changes` 回答。事件在服务端留最近 400 条并带递增序号，驱动者只要说清"上次看到第几条"，
断线重连也不会漏。

不要轮询也行：给了 `_meta.progressToken` 就把每条事件折成一句进度通知推回去，没给就不推——没要进度
还一直推，对方只是多收一堆噪音。用 MCP 而不是自己定一套 JSON：对方已经会说 MCP，自己定一套等于要求
每个接入方先写适配层，那这件事就不会发生。

## 网页壳与切换

页面上的目标能换来换去，而每次切换都新建 Runner 的话，切回去看到的是**另一条互不相干的历史**——
事件留痕、待确认的 diff、正在跑的子进程全在旧对象里，页面上只表现为"刚才那些怎么没了"。所以同一个
(工作区, 会话) 必须拿到同一个对象，"切换不杀任务"是这条的直接后果。

`/events` 在目标变了时必须**退订旧的 → 订阅新的 → 补一帧 state**：只换订阅不补帧，页面会停在旧目标
的事件流上，看起来"切了"、事件还是别人的。补帧判据看版本号而不只是 Runner 身份，否则一个周期里来回
切会既不换对象也不补帧。只有**显式**选择才写指针，内核推断出来的初始目标不写——那是推断，不是人选
的结果。

探活改到**后台**是因为它原来长在请求路径上：`/state` 与 `/target` 各同步探一次，模型连不上时要等
超时（实测 3.4 秒），于是"切个工作区"看起来像壳卡住了——而切换本身跟模型通不通毫无关系。请求路径
现在只读最近一次结果，并把"什么时候探的"（`probed_at` / `age_s`）一起交出去：陈旧值可以接受，
**静默的**陈旧值不行。新建会话同理走既有的 `create_session`（`POST /session/new`）：会话要**先真的存在**，
`/target` 才切得过去——它一直不肯替人静默新建。

## 权限与只读

绑非回环地址时不给远程可写：真开就得先想清楚鉴权与传输，不在本批。判据取**实际绑上的地址**而不是
命令行那层字符串——测试与嵌入代码直接构造服务、绕开的正是 CLI，安全边界不能靠"大家都会走命令行"
来成立；认不出来的名字按远程办。

拦的是**驱动**不是**看**：`/run` `/confirm` 403，`/target` 照常可用但**不落任何盘**（它改的只是进程
内视图）。落盘是另一回事——网页壳指向与工作区登记表都是机器级持久状态，而本批没有鉴权兜底。所以线
划在"改进程内视图可以，改机器级持久状态不行"。

## 长任务的等待

llama.cpp 生成本身是非流式的，整段生成完才返回，所以终端可能几分钟没有新行——那不是挂死，满 15 秒
打一行心跳，让"还在等"与"已经死了"能分开。超时是**回执**而不是失败：桥先回一句"我先不等了"，跑完
把结论补发（原先那句之后就没了下文，结论直接丢）。

同一个工作区同时只跑一轮，因为记忆 / 检查点 / 进度文件是同一份，并发只会让"它在做哪件事"变得说不清。

## 索引与记忆的口径

只有 Python 走 AST，别的语言是行首声明扫描——认得出"这个文件里有什么、大概在第几行"，不够回答"改
这里安全吗"，所以引用图与 `find_callers` 只对 Python 成立，别的语言上工具会明说"没查 ≠ 没有"。

冷记忆用 SQLite FTS5 而不是向量库：代码语境里讨论的多是独特标识符，关键词命中率本来就高。热记忆有
硬性容量上限，写满按优先级下沉——那不是限制，是代谢；长的内容不进热记忆，只把短 fact 蒸馏进库。

历史往来（`transcript`）**默认不进模型上下文**：短上下文正是靠不塞历史才成立的，把它塞回去等于把
「状态外置」这条设计推翻。要判断「这个问题是从哪来的」时，模型自己调 `search_history`（`spool session
search` 是它给人的同一入口）按关键词取回片段与会话/时间/角色——检索是**它主动做的一个动作**，不是每轮
注入的一段；命中为空时明说"没找到"以及**在哪个范围**里没找到，免得"没搜到"被读成"没发生过"。

## 测试与工具

`--provider fake` 只回放 `--script`，**不能写代码**，没有 LLM 时不要当兜底：把它当兜底的结果是"跑完
了但什么也没改"。`--check` 走的是**真正要跑的那条路**（包括 `--bridge-proxy`）——早先它没把代理传下
去，测的是直连，症状是"检查通过、真跑失败"。

偶发问题一律固定成确定性用例（例如让假服务端故意把两件事写进同一次 `sendall`）。
