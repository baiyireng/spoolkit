# 拒绝泄漏并补不足的节

状态：L0.10 完成。不改生产代码，不进入 L3.1。

## 固定条件

| 项 | 值 |
|----|----|
| 模型 | 本机 llama-server，`Qwen3.8-27B-UD-IQ2_S`，`n_ctx=8192` |
| 采样 | `temperature=0`，`seed=1`。同一篇的三次 repeat 正文相同 |
| 思考 | 请求带 `enable_thinking=false` |
| 文章 | 技术说明、项目复盘、方案对比。初稿沿用已经裁好的半句 |
| 流程 | 只跑 F：补当前节、一次 `write_pending`、不足的未开始节再 `repair_section`、通过后才 `finalize` |
| 预算 | `OfflineTokenCounter`。判定线是 `prompt + max_tokens <= 8000` |
| 样本 | 3 篇初稿 + 27 次新请求 |

脚本和记录在 `recon/continuation-spike-8/`。日志里没有密钥。初稿没有重新生成。

两处改动：

- 返回命中 `<think>`、`thinking` / `Let me` / `analysis`，或一段以英文为主且不少于 160 个拉丁字母的段落，整段拒绝，不写入正文。重试一次，指令是「只输出中文 Markdown 正文，不要思考过程/英文分析」。重试仍泄漏则整次失败。不把泄漏段删掉再算完成。
- `write_pending` 之后，只对没有标题或不足 450 字的未开始节补写。输入是标题、要点、距 500 字还差多少、该节最后 80 字。只补这一节，不写下一节，不写「完」。每节最多两次。全文仍有不足就不进入 `finalize`。

450 字和 3000 字沿用 L0.9，跑完没有改。这一轮的「每节」包括已经写过的节。可读性仍是同一个人按 L0.3 的尺子打的，不是盲评。

脚本自检覆盖了：泄漏段整段拒绝后，删掉标签的剩余英文仍然算泄漏；补写插回该节，下一节的字数不变；带泄漏的正文不能算完成。2000 个「甲」仍按 2000 token 计。

## 泄漏拒绝

27 次请求里有 3 次被拒绝，都是项目复盘补当前节的第一次返回。三次相同：1564 字，开头是 `<think>`，里面有 “Let me”，英文分析三档都命中。这三段留在请求日志里，没有进入正文。

每次拒绝后都重试了一次。重试返回 191 字中文，守卫通过，写进正文。重试从尾部窗口的「范模型的输出」另起一段，没有从「风格引导」最后一个字接上。正文里没有 `<think>`，也没有 “Let me”。

技术说明和方案对比的第一次返回就通过，没有重试。

## 预算

27 次请求全部满足 `prompt_tokens + max_tokens <= 8000`。最大合计是 4804。`OfflineTokenCounter` 比服务端 prompt 多 2 到 130 token，平均多 51，没有一次估小。

这 27 次合计 22575 token，耗时 469 秒。被拒绝的那 3 次也算在里面。

没有改产品代码，没有重跑 pytest。

## 决策

项目复盘和方案对比三次都真完成，正文里没有思考泄漏。拒绝后的重试三次都写成了中文。未开始节都超过 450 字，所以补写次数是 0。

技术说明的未开始节也过了 450，差在当前节「余量」414 字。这一轮约定只补未开始节，所以没有补它，也没有进入最后的「完」。按决策门，还差这一节，先把当前节放进同一条长度补写。不写 L3，不进入 L3.1。
