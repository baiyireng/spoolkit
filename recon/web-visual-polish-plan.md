## 结论

功能体验已经走到 M2-C1，但当前界面仍偏“工程师工具的第一版”：
**结构能用、信息齐全，但视觉层级、密度和移动端形态还没完成。**

这不靠零散调几个颜色解决，应该作为独立 M3 做一轮**克制的设计系统收口**：
暗色开发者工具、信息优先、低装饰、高一致性。

## 当前最明显的视觉问题

### 1. 顶栏仍以路径为主

- 桌面顶栏直接显示 `D:\workSpace\... · 会话 ...`，路径是主信息，项目/会话层级反了。
- 390 宽时路径换行，顶栏变成两行，挤掉内容高度。
- 没有品牌/产品锚点，也没有紧凑的状态入口。

### 2. 左栏密度高、层级弱

- 工作区、会话、未命名会话、测试目录全部同一视觉权重。
- 每行都有移除按钮，常驻可见，造成噪声。
- 没有搜索；临时目录（`spool-chat-*`、`tmp*`）占列表。
- 分组标题、选中态、运行态之间的差异主要靠很淡的背景和字号。

### 3. 对话流像“长文列表”，不像任务流

- 助手回复与背景的边界很弱；用户气泡和助手内容没有清楚的角色节奏。
- 长段落连续堆叠，缺少段落/列表/代码/轨迹之间的呼吸。
- `思考过程 0 行` 这类小开关视觉权重过低。
- 消息缺失时间/分组，长会话里很难定位。

### 4. 状态面板过大、过重

- 桌面打开时是一张很大的浮卡，抢过主对话的注意力。
- 移动端几乎盖住整个对话，且没有明显的 scrim/层级过渡；
  面板内容字号偏小、行距紧，像调试信息而不是可读的状态页。
- 关闭键和标题的层级可以更明确。

### 5. 输入条缺少“可输入区域”的容器感

- 输入框、发送键和背景的边界偏弱；placeholder 和提示字很小。
- 桌面和移动端的输入条形态不统一。

### 6. 全局 typography / spacing 没成体系

- 11–13px 的小字用得多，层级靠字号硬拉。
- 行高、圆角、间距、边框、阴影没有统一 scale。
- 暗色主题整体偏平，选中态/浮层/输入区缺少一致的 elevation 语言。

## M3 设计方向

**关键词：安静、清晰、开发者工具、信息优先。**

不要做：
- 大渐变、玻璃拟态、彩色大面积铺底；
- 每个模块一种圆角/阴影；
- 为了“好看”牺牲密度和键盘效率。

要做：
- 一套 token：颜色、字号、行高、间距、圆角、边框、elevation；
- 一套层级：背景 / 面板 / 浮层 / 强调；
- 一套响应式规则：桌面侧栏常驻，移动端抽屉 + 底部 sheet；
- 一套组件状态：default / hover / focus-visible / selected / running / disabled。

## M3 工作包

### M3-A：设计 token 与排版

- 字号 scale：11 / 12 / 13 / 15 / 18 / 24，正文 14–15，标签 ≥11.5。
- 行高：正文 1.55–1.6，紧凑列表 1.35–1.45。
- 间距：4 / 8 / 12 / 16 / 24 为主，减少随意 3/5/7/9px。
- 圆角：8 / 10 / 14 三档。
- elevation：surface / raised / overlay 三档；暗色优先边框+轻阴影，不靠大黑影。
- 颜色：保留现有语义色，但收敛强调色使用范围；选中态、运行态、危险态各一套。

### M3-B：壳层

- 顶栏：
  - 左侧品牌/产品锚点（可选小 `spool` 标记）；
  - 中间「工作区名 · 会话标题」，完整路径进 title；
  - 单行省略，不换行；
  - 右侧状态收敛成一枚紧凑 chip，点开详情。
- 左栏：
  - 搜索框；
  - 分组标题更清楚；
  - 行高/内边距统一；
  - 移除按钮 hover/focus 才强化，触屏仍可见；
  - 临时目录默认隐藏（由 M2-C2a 完成行为）。
- 输入条：
  - 明确的容器（边框/底色/轻阴影）；
  - placeholder 与提示字号提升；
  - 发送键与停止键状态一致；
  - 移动端安全区。

### M3-C：对话流

- 用户消息：右侧气泡，保留当前形态，优化内边距/最大宽度/时间。
- 助手消息：
  - 用轻微容器或左侧边界建立“回答块”，与背景分开；
  - 段落/列表/表格/代码块之间统一垂直节奏；
  - 长回答的标题层级更明显。
- 轨迹开关：提高可发现性，但保持低调。
- 消息分组/时间：长会话可定位。
- 空态、失败态、重试态统一视觉语言。

### M3-D：状态面板与移动端

- 桌面：小尺寸 popover，锚在右上，最大宽度约 360，内容滚动，轻阴影；不要盖住主对话的大块。
- 移动端：底部 sheet 或全屏 dialog：
  - 有 scrim；
  - 顶部标题 + 关闭；
  - 内容可滚动；
  - 不与输入条/通知重叠；
  - 关闭后焦点回到触发徽标。
- 移动端顶栏单行省略；抽屉/搜索/设置保持同一套 sheet 语言。

### M3-E：视觉验收

- 1440×900、1024×768、390×844；深色/浅色。
- 场景：空态、普通对话、长回答、状态面板、通知、待确认 diff、命令卡、组合卡、设置、抽屉、失败/重试。
- 检查：
  - 顶栏不换行、不压状态；
  - 侧栏行高/层级/选中态一致；
  - 助手/用户消息边界清楚；
  - 状态面板不遮主内容（移动端有 scrim）；
  - 输入条像可输入区域；
  - 无 <11px 正文、无对比度回归、无 44px 以下移动触控目标。

## 与功能路线的关系

建议顺序：

```text
M2-C2a  顶栏 + 搜索 + 临时目录（先做行为）
  ↓
M3      视觉系统 + 壳层 + 对话流 + 移动端（本计划）
  ↓
M2-C2b  重命名（写接口 + 视觉入口）
  ↓
P1-15   标题生成与下一轮抢模型
  ↓
P2      剩余打磨
```

原因：C2a 会先动顶栏和侧栏，M3 在其上做视觉收口，避免两轮改同一块；
C2b 的重命名入口也应该长在稳定的视觉系统上。

## 验收原则

- **先统一，再个性化**：token 和组件状态先落地，再讨论单点装饰。
- **每改一处都截图对比**：桌面/移动、深/浅。
- **不牺牲信息密度与键盘路径**：视觉打磨不能把侧栏变宽、行变高到低效。
- **不引入 UI 框架**：继续 CSS + 原生 DOM，保持离线与轻量。
