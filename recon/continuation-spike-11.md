# 按目标补写和脚手架守卫

状态：L0.13 完成。不改生产代码，不进入 L3.1。

## 固定条件

| 项 | 值 |
|----|----|
| 模型 | 本机 llama-server，`Qwen3.8-27B-UD-IQ2_S`，`n_ctx=8192` |
| 采样 | `temperature=0`，`seed=1`。同一篇的三次 repeat 正文相同 |
| 思考 | 请求带 `enable_thinking=false` |
| 文章 | 技术说明、项目复盘、方案对比。初稿沿用已经裁好的半句 |
| 流程 | 仍是 F。改写或补写之后重查全部标题，不足的节继续补，每节最多 3 次 |
| 预算 | `OfflineTokenCounter`。判定线是 `prompt + max_tokens <= 8000` |
| 样本 | 3 篇初稿 + 84 次新请求 |

脚本和记录在 `recon/continuation-spike-11/`。日志里没有密钥，模型名记为 local。初稿没有重新生成。

三处改动，跑模型之前定下，跑完没有改：

- 每次 `rewrite_current` 或 repair 之后重查全部标题。不足 450 字或不是完整句的节继续补。每节最多 3 次。改写成功只替换当前节，全文不过就不写「完」。
- 行首标签命中「要点」「目标剩余字数」「本节目标」「提示词」「指令」「大纲」时，整段不写入。再用「只输出正文，不复述提示词结构。」重试一次。仍命中则这次失败。句子中间的「系统提示词」「指令」「大纲」不算标签，否则技术说明和方案对比里已有的正文会被误伤。
- `anchor_lost` 之后仍走改写。改写之后回到全文校验，不因为这一节过了就判整篇完成。重复结尾仍按上一轮的 novelty 规则拒绝。

450 字和 3000 字沿用上一轮。可读性仍是同一个人按 L0.3 的尺子打的，不是盲评。

脚本自检覆盖了：上一轮那种「要点：」「目标剩余字数：」算脚手架；「系统提示词」「固定的指令」「抄大纲」不算；改写后的一节够长，旁边还有短节时，整篇不算完成。2000 个「甲」仍按 2000 token 计。

## 补写次数

技术说明仍是「余量」一次补写。9 token 的重复结尾被 novelty 拒绝，重试是一句新话，414 变成 479。后面三节一次写完。

项目复盘每次 1 次改写、7 次补写。「结果」补了 3 次：320 → 367 → 442 → 484，第三次过了 450。「原因」补了 2 次，到 462。「改法」补了 2 次，停在 408。第二次补写的重试仍在重复已有句子，重叠 0.92，novelty 判失败，这次停下，没有写「完」。「下一步」因此停在 `write_pending` 的 329 字，没有进入补写。

方案对比没有补写，没有改写。全文 4163，和上一轮相同。

## 脚手架

6 次命中都在项目复盘的「改法」。模型把提示里的「要点：」「目标剩余字数：」写进了返回。两次都整段拒绝，没有进入正文。

第一次的脚手架重试没有标签，但把已有结尾句又写了一遍，重叠 0.31，novelty 拒绝。随后那次 novelty 重试是新段落，重叠 0，写入后「改法」从 298 到 408。第二次的脚手架重试重叠 1.0，novelty 重试重叠 0.92，都没有写入。正文里没有「目标剩余字数」。句子里的「罗列要点」留着，它不是行首标签。

## 锚点

项目复盘三次都先泄漏思考段，重试从「范模型的输出」另起，记 `anchor_lost`。这段没有进入正文。改写替换了「过程」，559 字，完整句，无 think，和旧正文、要点的重叠都是 0。随后全文继续查，结果「改法」和「下一步」不够 450，整篇不算完成。

## 预算

84 次请求全部满足 `prompt_tokens + max_tokens <= 8000`。最大合计是 4804。`OfflineTokenCounter` 比服务端 prompt 多 2 到 128 token，平均多 42.6，没有一次估小。

这 84 次合计 32373 token，耗时 497.7 秒。被拒绝的补写、思考段、脚手架和 `anchor_lost` 重试都算在里面。novelty 拒绝 27 次。脚手架重试 6 次。

没有改产品代码，没有重跑 pytest。

## 决策

技术说明 3/3，方案对比 3/3。项目复盘 0/3。「结果」第三次补到 484，但「改法」408、「下一步」329。脚手架被拦住了，没有进入正文。`anchor_lost` 改写后仍做了全文校验，没有直接通过。

项目复盘仍有单节不足。先修 repair loop，不写 L3，不进入 L3.1。
