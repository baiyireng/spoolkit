# 设计取舍与实测教训

对外文档只讲"怎么用"；这一页收录**长段理由**：为什么这么定、不这么定会怎样。每条只给结论与
指针，详细推演与实测在 [`dogfooding.md`](dogfooding.md) 与 [`superpowers/specs/`](superpowers/specs/)。

## 配置三层

命令行 > 环境变量 > 用户配置 > 内置默认，因为它们是三种不同寿命的意图：命令行是"这一次"、环境
变量是"这个 shell"、配置文件是"长期"。缺少用户级那层时，同一配置每天都要重打一遍
`--provider llamacpp --base-url …`；重复输入的后果是有人写一个 `.bat`，此后无人知道生效的配置在哪。

密钥只放 `.env`、非密钥默认值只放 `config.toml`：`config.toml` 的键是白名单（写错一个字母的症状
是"设置了却没生效"，最难排查），而密钥需要能随时新增、能被 `.gitignore` 一句话排除。

## cwd 契约

CLI 认当前目录（向上查找 `.agent/`），机器级入口不认。说不清时要求用户点名，不用"站在哪个目录"
顶替——猜错的症状是"这个命令的记忆与别的命令不是同一份"。

2026-09-27 的事故：在 `C:\Users\32615` 起桥，它读 `C:\Users\32615\.env`，而凭据在
`D:\workSpace\agentWorkSpace\.env`；更严重的是 `cwd/.env` 在解析顺序里**排在用户级前面**，于是
"照提示在当前目录建 .env"静默覆盖了正确配置。现在的规矩是没给 `--root` 就是 `None`，
凭据只从用户级那层来。

迁移口径：`serve` / `hub` 不给 `--root` 时不再认 cwd，是本批唯一一处静默改变的老行为。唯一例外是
机器级桥在登记表为空时退回启动目录——否则装机第一天无法完成第一次配对；这条兜底刻意限定在
"未登记任何工作区"。

## 机器级入口与短命令

网页壳本身是机器级的（不认 cwd），但名为 `hub`；"在任意目录即可起步"上，**名字短本身即占
一半作用**。因此有了 `spool web` / `spool qq` 两条短写；`serve` / `hub` / `bridge`
原样保留、语义不变——改长命令等于改既有行为。

`[channel.<名字>]` 只给短命令当默认值，`bridge` 的参数默认值未变。那节里的 `root` 认但不读：
工作区在早得多的一步就解析完，此后拿配置去补等于改掉"服务整台机器"这条契约。

## 通道与凭据

默认**配对**而不是默认放行：公网通道加一个能驱动工作区的 agent，默认放行是致命的（第三方 hook 的
访问控制在名单为空时会放行任何发送者，这正是要避免的）。

放行是**身份级**的（哪条通道 + 哪个用户 → 能使用哪几个工作区），与工作区解耦，因此换工作区不需重新
配对。凭据链只有一处实现，因为三处各写一套的后果是"这条命令能读到、那条读不到"，而报错都写着
"没配"。

通道本身是**可装载**的（entry point 组 `spoolkit.channels`，或环境变量
`SPOOLKIT_CHANNEL_PLUGINS`）：核心不认识任何一家通道，接入新通道不必改核心。**个人微信与个人 QQ
没有公开的官方接口**——第三方 hook（itchat / wechaty / NapCat 之类）违反服务条款、有封号风险，而且
等于绕过配对、长度上限、授权三件事，因此本包只做官方通道。

## 长连接与渲染

QQ 网关的心跳与握手字节流各有一处真机才暴露的时序缺陷（心跳迟发被判掉线；握手时多读到的
数据帧被丢弃，症状为"偶发连不上"，单跑通过、全量运行才失败）。两条都已修复，其中丢帧一条已固定为
确定性用例——偶发问题不固定成用例就无法防止复发。

手机上显示的文字按各通道渲染能力处理（只动标记、不改内容）：要求模型"不要写 Markdown"既不可靠，
又占用本项目最关键的资源（上下文预算）。

## 异步与协议

MCP 的一次 `tools/call` 是请求/响应，而这里的任务可以运行数十分钟；做成同步，调用方只能空等或
超时，两种结果都不可取。因此 `delegate_task` 立即返回 task_id，进度靠 `task_status` /
`task_events` 轮询，审批靠 `confirm_changes` 回答。事件在服务端留最近 400 条并带递增序号，驱动者
只要说明"上次看到第几条"，断线重连也不会漏。

也可以不轮询：给出 `_meta.progressToken` 后把每条事件折成一句进度通知推回，未给出则不推——未请求
进度仍推送只会增加无关消息。选择 MCP 而不是自定一套 JSON：接入方已支持 MCP，自定一套
等于要求每个接入方先写适配层，那这件事就不会发生。

## 网页壳与切换

页面上的目标可以更换；若每次切换都新建 Runner，切回去看到的是**另一条互不相干的历史**——
事件留痕、待确认的 diff、正在跑的子进程全在旧对象里，页面上只表现为"刚才那些怎么没了"。因此同一个
(工作区, 会话) 必须拿到同一个对象，"切换不终止任务"是这条的直接后果。

`/events` 在目标变化时必须**退订旧的 → 订阅新的 → 补一帧 state**：只换订阅不补帧，页面会停在旧目标
的事件流上，看起来"切了"、事件仍是别人的。补帧判据看版本号而非 Runner 身份，否则一个周期里来回
切换既不换对象也不补帧。只有**显式**选择才写指针；内核推断出的初始目标不写——那是推断，不是人选。

探活改到**后台**是因为它原先在请求路径上：`/state` 与 `/target` 各同步探一次，模型连不上时要等
超时（实测 3.4 秒），于是"切换工作区"表现为壳无响应——而切换本身与模型是否可达无关。请求路径
现在只读最近一次结果，并把"何时探测"（`probed_at` / `age_s`）一并交出：陈旧值可以接受，
**静默的**陈旧值不行。新建会话同样走既有的 `create_session`（`POST /session/new`）：会话必须
**先真的存在**，`/target` 才切得过去——该端点不代替用户静默新建。

## 权限与只读

绑非回环地址时不开放远程可写：真要开放得先确定鉴权与传输方案，不在本批范围。判据取**实际绑上的
地址**而不是命令行那一层的字符串——测试与嵌入代码会直接构造服务、绕开 CLI，安全边界不能建立在
"都会走命令行"这一假设上；无法识别的名字按远程处理。

拦的是**驱动**，不是**查看**：`/run` `/confirm` 返回 403，`/target` 照常可用但**不落任何盘**（它改的
只是进程内视图）。落盘属于另一类：网页壳指向与工作区登记表都是机器级持久状态，而本批没有鉴权兜底，
因此界线划在"改进程内视图可以，改机器级持久状态不行"。

## 长任务的等待

llama.cpp 生成是非流式的，整段生成完才返回，因此终端可能几分钟没有新行——那不是挂死：满 15 秒
打一行心跳，使"仍在等待"与"已经失败"可区分。超时是**回执**而不是失败：桥先回
「这一轮已超过 N 秒仍未结束，不再等待」，跑完再把结论补发（原先那句之后没有下文，结论丢失）。

同一个工作区同时只跑一轮，因为记忆 / 检查点 / 进度文件是同一份，并发只会让"它在做哪件事"无法说清。

## 索引与记忆的口径

只有 Python 走 AST，其它语言用行首声明扫描——能认出"这个文件里有什么、大致在第几行"，不足以回答
"改这里安全吗"，因此引用图与 `find_callers` 只对 Python 成立，其它语言上工具会明说"这里的
「没有调用方」等于「没查」，不等于「没有」"。

冷记忆用 SQLite FTS5 而不是向量库：代码语境里讨论的多是独特标识符，关键词命中率本就高。热记忆有
硬性容量上限，写满时按优先级下沉；长的内容不进热记忆，只把短的 fact 蒸馏进库。

历史往来（`transcript`）**默认不进模型上下文**：短上下文靠不塞历史才成立，塞回去等于推翻
「状态外置」这条设计。需要判断「这个问题是从哪来的」时，模型自己调 `search_history`（`spool session
search` 是它给人的同一入口）按关键词取回片段与会话/时间/角色——检索是**它主动执行的一个动作**，不是
每轮注入的一段；命中为空时明说"没找到"以及**在哪个范围**内没找到，避免"没搜到"被读成"没发生过"。

检索的作用域**默认只到当前会话**：历史按会话划分，"我在 A 里说过的话"不应被 B 里的一次检索带出——
那不属于能力，而是未经声明的越界。要跨会话就**显式**指定（`session="*"` / `--all-sessions`），
那一次结果里每条都标出来源会话；工作区边界不变（历史按工作区分库存，跨工作区不查）。

上下文里另带一段**有界摘要**（更早那几轮，条数与字符预算都是标定值）：小模型不会主动检索——它不知道
自己缺什么，因此"要不要结合上下文"不能全押在它身上。摘要必须保持有界：每条截断、总量封顶（默认 400
字符的量级），**绝不把历史原文整段塞回去**，否则上面那条"历史不进上下文"随即失效；它同样过
`redact_secrets`，因为进入的是模型上下文。

## 测试与工具

`--provider fake` 只回放 `--script`，**不能写代码**，没有 LLM 时不要当兜底：把它当兜底的后果是"运行
结束但没有任何改动"。`--check` 走的是**真正要执行的那条路**（包括 `--bridge-proxy`）——早先它没把
代理传下去，测的是直连，症状是"检查通过、真跑失败"。

偶发问题一律固定成确定性用例（例如让假服务端故意把两件事写进同一次 `sendall`）。

验证按产出类型分派：`verify_file` 一个入口按扩展名决定怎么验（`.html` 结构/内联 JS/id 引用/本地资源、
`.js` / `.py` / `.json` / `.toml` / `.css`），自动验证走同一套，验不了的那一步明说"查不了"。
